## 给 UI 优化 AI 的项目上下文

这是一个基于开源 `TS3AudioBot` 的 TeamSpeak 音乐机器人项目，项目分支名为“波点音乐”。它通过 `KuwoMusicPlugin` 搜索和播放酷我音乐，并提供一个独立网页控制台，让用户在浏览器中完成登录、搜索歌曲、播放、管理待播队列和管理机器人。

本次交接只针对网页 UI/UX 优化。不要因为优化页面而改动 TeamSpeak 连接、音乐播放、酷我 API、权限后端、更新下载流程或本地语音识别逻辑。

## 技术栈与代码位置

- 前端目录：`WebInterface/`
- 框架：Vue 2、TypeScript 3.9、Vue Router 3
- UI 依赖：Buefy 0.8、Material Design Icons、Less、Webpack 4
- 前端入口：`WebInterface/src/ts/Main.ts`
- 全局样式和设计变量：`WebInterface/src/ts/App.vue`
- 控制台 API 封装：`WebInterface/src/ts/ConsoleApi.ts`
- 后端项目：`TS3AudioBot/`
- 音乐插件：`KuwoMusicPlugin/`
- 传统 TS3 API 和旧版页面仍然保留，不要随意删除兼容代码。

项目文件可能包含 UTF-8 中文。读取 Markdown、Vue、TypeScript 文件时请使用 UTF-8，避免把中文误判为乱码。

## 当前网页路由

- `/`：登录、首次创建网页管理员、首次连接机器人。
- `/music`：点歌主页，搜索歌曲并播放或加入待播队列。
- `/recent`：最近播放。
- `/admin`：管理员页面，包含更新、服务日志、站点名称、机器人、语音控制和网页账号管理。

`Main.ts` 当前只注册了上述新控制台路由。仓库里还保留旧版页面和组件，例如 `Pages/Bot.vue`、`Pages/Bots.vue`、`SettingsGroup.vue`、`SettingsField.vue` 等。旧版页面使用 Buefy 的原生卡片、英文标签和旧式布局，是当前 UI 不统一的重要来源。不要把旧版原生设置界面直接暴露到新控制台中。

## 当前活跃界面结构

### 全局壳层

文件：`Components/ConsoleShell.vue`

- 桌面端：左侧固定导航、顶部搜索栏、账号区域、主内容区、底部固定播放器。
- 移动端：隐藏桌面侧栏，使用底部图标导航。
- 顶部账号区：显示当前控制的机器人名称、连接状态圆点和退出登录按钮。
- 管理员可以在侧栏底部看到版本号和更新入口。
- 连接状态通过 `/console-api/bots` 每 5 秒轮询，状态为 `connected`、`connecting` 或 `offline`。

### 点歌与最近播放

文件：`Pages/ConsoleOverview.vue`

- 通过顶部搜索框触发 `music/search`。
- 搜索结果显示封面、歌名、播放和加入待播操作。
- 页面每 5 秒刷新 `music/state`。
- 页面顶部有“控制机器人”选择器，多机器人时必须明确当前操作对象。
- 普通用户可以搜索、播放、加入待播、暂停、继续、上一首、下一首等正常操作。
- 管理员才可以清空整个待播队列。

### 底部播放器

文件：`Components/ConsolePlayerBar.vue`

- 显示当前歌曲封面、歌名、播放/暂停、上一首、下一首、进度、循环、随机、音量和待播队列入口。
- 点击当前歌曲区域可以展开歌词界面。
- 歌词通过 `music/lyrics` 获取，使用 `requestAnimationFrame` 做本地进度推进和当前歌词定位。
- 当前播放条在桌面端固定在底部，在移动端必须避开浏览器安全区域和底部系统栏。

### 待播队列

文件：`Components/ConsoleQueueDrawer.vue`

- 桌面端从右侧滑出。
- 移动端从底部弹出。
- 当前播放项高亮，其他队列项可以点击并立即切换播放。
- 管理员看到“清空待播队列”，普通用户不应看到这个操作。
- 关闭按钮和队列项目的点击区域必须清晰，不能出现按钮歪斜、难点或误触。

### 管理员页面

文件：`Pages/ConsoleAdmin.vue`

当前包含：

- 程序更新
- 服务与日志
- 站点名称
- 音乐机器人列表与编辑
- 新建机器人
- 语音控制
- 网页账号和密码管理
- 重启/停止服务的二次确认弹窗

语音控制是一个完整的全局开关，不要拆成“暂停可用、点歌不可用”之类的多个小开关。默认关闭；默认唤醒词是“音乐机器人”，唤醒词可以在后台自定义，并且独立于机器人的显示名称。

## 已确认的产品与 UI 要求

### 必须保持

- 页面首先服务于点歌和播放，不要做营销型首页或大段功能介绍。
- 机器人名称应优先显示实际被控制的机器人名称，不要固定写“波点音乐”代替机器人名称。
- 普通用户和管理员的操作边界必须清楚，不能让普通用户看到管理入口、清空队列、服务控制等操作。
- 退出登录必须固定在桌面端顶部账号区域，不能掉到页面底部或移动到容易误触的位置。
- 连接状态圆点必须真实反映当前机器人状态。已连接时必须明显亮起，不能因为轮询或状态映射问题一直显示灰色。
- 页面中不要增加没有价值的解释性小字，例如“版本号来自某某公开下载站”之类的描述。版本区域只保留版本、更新状态和必要操作。
- 不要把旧版原生设置界面直接露出来。已有设计过的控制台要保持同一套视觉语言，旧设置项要翻译、分组或迁移到自定义页面。
- 所有主要按钮、图标按钮、输入框、弹窗和空状态都要有完整状态：加载中、禁用、失败、成功、空数据和移动端布局。
- 播放器、队列和歌词必须在手机浏览器底部地址栏/手势区域存在时仍可操作，不能遮挡返回、关闭或播放控制。

### 当前明确的交互验收点

1. 桌面端顶部：返回/前进按钮如果保留，必须让用途明显；如果不是产品核心能力，可以弱化或移除，但不要留下用户看不懂的装饰性控件。
2. 顶部连接指示：连接成功显示明显的绿色状态，连接中显示警示色，离线显示灰色或错误色，并配合可理解的无障碍文本。
3. 退出登录：只保留在顶部账号区域，桌面和移动端都不能与主要播放操作混在一起。
4. 正在播放按钮：播放和暂停状态必须一眼可区分，按钮视觉层级要高于循环、随机等次要操作。
5. 待播列表：点击非当前歌曲可以直接切歌；当前歌曲只显示状态，不应造成重复操作；关闭按钮应居中、对齐并有足够点击面积。
6. 歌词页：移动端使用 `100dvh`、`env(safe-area-inset-bottom)` 等方式处理可用高度；返回播放器按钮始终可见，不被浏览器底栏和固定播放器遮挡。
7. 语音控制卡片：保持在自定义管理员页面内，不要重新暴露原生设置组件；文案简短，不要堆叠语音识别原理说明。

## 视觉方向

当前全局设计变量在 `App.vue` 中：浅灰画布、白色表面、深色文字、青绿色品牌色、细边框和轻阴影。已有设计方向是干净、安静、工作型的音乐控制台，不是娱乐产品营销页。

建议继续沿用：

- 浅色背景和白色内容表面。
- 青绿色作为品牌色和主要动作色，但不要把所有文字和按钮都染成青绿色。
- 文字优先于装饰，信息密度适中，支持快速扫描。
- 桌面端使用稳定的侧栏/顶部/底部播放器布局。
- 移动端优先保证播放、队列、歌词和返回操作的可用性。
- 使用现有 Material Design Icons 或 Buefy 图标，不要用随意的 Unicode 字符替代所有图标。
- 按钮、输入框、列表行和播放器控件尺寸稳定，长歌名使用省略或换行规则，不能撑破布局。
- 卡片圆角和阴影要克制，不要出现卡片套卡片、装饰性渐变球、模糊光斑或大面积营销式 Hero。

## API 和数据契约

前端通过 `ConsoleApi.ts` 调用 `/console-api/`，使用同源 Cookie 会话：

- `status`、`login`、`setup`、`setup/bot`、`me`、`logout`
- `bots`、`bots/voice`
- `music/state`、`music/search`、`music/play`、`music/add`
- `music/pause`、`music/previous`、`music/next`
- `music/volume`、`music/loop`、`music/random`、`music/clear`
- `music/lyrics`
- `settings/brand`
- `update/status`、`update/check`、`update/apply`
- 服务日志、重启和停止相关接口

不要为了 UI 改动去修改这些路径、请求方法、权限语义或返回字段。需要新增 UI 状态时，优先使用已有 `MusicState`、`ConsoleBot`、`Track`、`TrackResource` 类型。

## 语音功能的边界

- 语音识别是可选的本地功能，默认关闭。
- 使用本地 Vosk 中文模型，不上传或长期保存原始语音。
- 需要先说唤醒词，再说暂停、继续、下一首或带歌曲名的播放指令。
- UI 只负责开关、机器人选择、唤醒词编辑和保存反馈，不要在 UI 中承诺准确率、延迟或 CPU 表现。
- 当前源码包含之前的本地语音识别实验改动，UI 优化时不要修改 `TS3AudioBot/Audio/`、`TSLib/` 或相关发布文件。

## 当前已知 UI 技术债

- 新版 `ConsoleShell` 和旧版 Buefy 页面并存，视觉和语言不一致。
- 仓库中仍有英文或未完成文案，例如 `Settings`、`Playlists`、`History [WIP]`、`Search [WIP]`、`Hello` 占位内容等；先判断页面是否仍在当前路由中，再决定翻译、隐藏或删除。
- 部分新页面使用自定义 HTML/CSS，部分旧页面依赖 Buefy，响应式行为不完全一致。
- 连接状态依赖轮询，UI 不能只根据“页面加载成功”判断机器人已连接。
- 播放器是固定定位组件，任何高度、层级或移动端改动都必须检查队列抽屉和歌词展开状态。
- 项目使用 Vue 2，不能直接引入只支持 Vue 3 的组件库。
- 不要复制 CeruMusic 的源码、Logo、插画、字体或媒体资源；只能借鉴信息架构和交互框架。

## 推荐优化顺序

1. 先检查当前实际路由和组件，删除/隐藏无效的旧入口和未完成标签，统一中文文案。
2. 修复 `ConsoleShell` 的连接状态、账号/退出位置、返回前进控件和桌面/移动端导航。
3. 修复 `ConsolePlayerBar` 的播放按钮层级、歌词展开返回、底部安全区域和播放状态反馈。
4. 修复 `ConsoleQueueDrawer` 的关闭按钮、列表点击切歌、当前项状态和移动端抽屉高度。
5. 统一搜索结果、最近播放、空状态、错误状态、加载状态和管理员卡片的视觉系统。
6. 最后再做颜色、间距、字体、图标和动效微调，不要先做大范围重构。

## 交接结论

这是一个已经具备完整点歌、播放、队列、歌词、账号、机器人管理和本地语音控制能力的控制台项目。当前最重要的 UI 工作不是增加更多功能，而是清理新旧界面混用造成的突兀感，统一中文和机器人命名，修复连接状态、退出位置、播放器、队列和歌词在桌面/移动端的可用性，并保持已有后端契约不变。
